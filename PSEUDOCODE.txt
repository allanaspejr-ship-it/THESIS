ALGORITHM: Agus Cascade Day-Ahead Hydropower Forecasting Study

INPUT:

    hydrologic, date, and time variables

OUTPUT:
    Cleaned hourly dataset
    Planned outage template

    24-hour day-ahead forecast workbooks

BEGIN
    Run Cell 1 to clean and resample raw data.
    Run Cell 2 to train or load the RBFNN and generate forecasts.
    Run Cell 3 to train or load benchmark models and generate forecasts.
    Run Cell 4 to generate thesis figures and organized result files.
    Use the Streamlit dashboard for operational execution and review.
END


============================================================
2. CELL 1: DATA CLEANING AND OUTAGE TEMPLATE GENERATION
============================================================

ALGORITHM: Clean Raw Agus Hydropower Dataset

INPUT:
    data/DATA(JAN2024-JUNE2025).xlsx

OUTPUT:
    outputs/cleaned_data/cleaned_hourly_data.xlsx
    outputs/cleaned_data/cleaned_hourly_data.parquet
    outputs/cleaned_data/cell1_metadata.json
    outputs/outages_planning/Planned_Outages_Input.xlsx

BEGIN
    Set cleaning configuration:
        plants = agus1, agus2, agus4, agus5, agus6, agus7
        short zero run threshold = 2 records
        long zero run threshold = 3 records
        short missing gap threshold = 2 records
        spike factor = 3.5
        KNN neighbors = 5

    Read the raw Excel workbook without assuming a single header row.

    Flatten the three-row source header:
        Forward-fill upper header rows.
        Sanitize text into lowercase underscore column names.
        Combine header levels into one machine-readable column name.
        Ensure duplicate column names are made unique.

    Standardize columns:
        Rename plant, unit, generation, outage, gate, elevation, and rainfall
        fields into consistent internal names.

    Consolidate rainfall fields:
        IF rainfall columns exist THEN
            Convert rainfall candidates to numeric values.
            Combine them into one rainfall column.
        ELSE
            Continue without rainfall.
        END IF

    Build datetime:
        Convert date column to date values.
        Convert time column to numeric hour values.
        Compute datetime = date + (time - 1) hours.
        Sort all records by datetime.

    Identify column groups:
        Generation columns
        Outage/status columns
        Hydrologic and operational context columns

    FOR each numeric cleaning column DO
        Convert values to numeric.
        Interpolate short missing gaps.
        Treat short zero runs as missing and interpolate them.
        Preserve long zero runs as real unit shutdowns.
        Smooth isolated spikes using neighboring values.
    END FOR

    Apply KNN imputation:
        Select remaining numeric columns.
        Use KNNImputer with configured neighbor count.
        Fill remaining missing numeric values.

    Derive plant totals:
        FOR each plant DO
            Sum cleaned unit generation columns.
            Save total_gen_<plant>.
        END FOR

    Derive unit outage/status:
        FOR each unit generation column DO
            IF generation is greater than zero THEN
                Set unit status to 1.
            ELSE
                Set unit status to 0.
            END IF
        END FOR

    Standardize outage/status values:
        Clip status fields into the range 0 to 1.
        Round status fields to binary values.

    Resample to hourly frequency:
        Set datetime as the time index.
        Resample records to hourly intervals.
        Average numeric values within each hour.
        Restore outage/status fields as binary values.

    Keep only downstream columns required by training and forecasting.

    Prepare public cleaned output:
        Rename internal columns into final output names.
        Keep date and time fields usable for downstream scripts.
        Omit internal datetime from public cleaned files.

    Save cleaned data:
        Write Excel cleaned data.
        Write Parquet cleaned data.
        Format Excel workbook.
        Write metadata including latest timestamp, row count, columns,
        and rainfall availability.

    Generate planned outage template:
        Sort cleaned data by datetime.
        Get the latest available historical row.
        Create 24 forecast hours for the next day.
        FOR each outage/status column DO
            Copy the latest known status into all 24 forecast hours.
            Use 1 if no status is available.
        END FOR
        Save Planned_Outages_Input.xlsx.
        Format the workbook.

END


============================================================
3. FEATURE ENGINEERING FOR MODELING
============================================================

ALGORITHM: Build Forecasting Features

INPUT:
    Cleaned hourly dataset

OUTPUT:
    Plant-level modeling frame with lag, rolling, outage, hydrologic,
    calendar, and cascade features

BEGIN
    Rebuild datetime from date and time fields when needed.

    Add calendar features:
        hour of day
        day of week
        month
        day of year

    FOR each plant DO
        Define target generation column:
            total_gen_<plant>

        Add lag features for target generation:
            lags = 1, 2, 3, 6, 12, 24, 48, 72, 168 hours

        Add rolling statistics:
            windows = 3, 6, 12, 24, 48, 168 hours
            compute rolling mean and related summary features

        Add residual/delta target:
            current generation = generation at time t
            next generation = generation at time t + 1
            delta target = next generation - current generation

        Add unit outage/status features.

        Add unit-share and available-capacity context where available.

        Add upstream cascade features:
            Agus 2 receives Agus 1 context.
            Agus 4 receives Agus 2 context.
            Agus 5 receives Agus 4 context.
            Agus 6 receives Agus 5 context.
            Agus 7 receives Agus 6 context.

        Add hydrologic context such as rainfall when present.

        Remove rows that cannot support lagged or target values.
    END FOR
END


============================================================
4. CHRONOLOGICAL TRAINING, VALIDATION, AND TESTING SPLIT
============================================================

ALGORITHM: Split Time Series Without Shuffling

INPUT:
    Plant-level feature dataset

OUTPUT:
    Training set
    Validation set
    Testing set

BEGIN
    Sort records by datetime.

    Let n = number of rows.
    Let train_end = floor(0.70 * n).
    Let validation_end = floor(0.85 * n).

    Training set = rows from start to train_end.
    Validation set = rows from train_end to validation_end.
    Testing set = rows from validation_end to end.

    Do not shuffle rows.
    Fit scalers and model parameters using training rows only.
    Use validation rows for tuning and model selection.
    Use testing rows only for final evaluation.
END


============================================================
5. RBFNN MODEL TRAINING AND SELECTION
============================================================

ALGORITHM: Train Cascade-Aware, Outage-Aware RBFNN

INPUT:
    Cleaned hourly dataset
    Planned outage template

OUTPUT:
    Saved RBFNN models per plant
    Saved scalers and metadata
    Validation/testing metrics
    RBFNN day-ahead forecast workbook

BEGIN
    Load cleaned data and planned outage input.
    Rebuild runtime-compatible datetime and feature columns.
    Add forecasting features.

    FOR each plant in the Agus cascade DO
        Select feature columns for the plant.
        Run leakage audit on selected features.

        Split plant data chronologically into:
            training
            validation
            testing

        Fit input scaler on training features only.
        Fit output scaler on training residual/delta target only.

        Build candidate RBFNN configurations:
            center counts
            learning rates
            gamma initial values
            batch sizes
            patience values

        FOR each candidate configuration DO
            Build RBFNN:
                Input layer receives scaled feature vector.
                RBF hidden layer computes Gaussian radial basis activations.
                Linear output layer predicts scaled residual/delta generation.

            Initialize RBF centers using K-means clustering on scaled
            training features.

            Train the model on the training split.
            Monitor validation loss for early stopping.

            Predict validation residual/delta values.
            Convert residual/delta predictions back to generation levels using
            persistence anchoring.
            Tune shrinkage and bias on validation data only.
            Compute validation metrics:
                operational MAPE
                MAE
                RMSE
                R2

            Store candidate score and candidate metadata.
        END FOR

        Select finalist candidates based on validation-aware score.

        FOR each finalist candidate DO
            Run rolling 24-hour validation day-ahead backtest.
            Score candidate using operational MAPE, RMSE, and R2-aware penalty.
        END FOR

        Select the best RBFNN candidate for the plant.

        Tune additional validation-only corrections:
            bin-level calibration
            hourly correction
            same-hour profile blending
            ramp limiting where applicable

        Evaluate final selected model on validation and testing sets.
        Save:
            Keras RBFNN model
            input scaler
            output scaler
            selected feature list
            plant metadata
            calibration information
            training and validation loss history
            validation/testing metrics
    END FOR

    Save leakage audit and model selection audit files.
    Generate operational 24-hour RBFNN forecast using saved model artifacts.
    Save RBFNN forecast to Excel and CSV.
    Run leakage-safe rolling day-ahead validation/testing backtests.
    Save day-ahead predictions and metrics.
END


============================================================
6. RBFNN FORECAST-ONLY OPERATION
============================================================

ALGORITHM: Generate RBFNN 24-Hour Forecast From Saved Models

INPUT:
    cleaned_hourly_data.parquet or cleaned_hourly_data.xlsx
    Planned_Outages_Input.xlsx
    Saved RBFNN model artifacts

OUTPUT:
    Day_Ahead_24H_RBFNN_Forecast.xlsx
    Day_Ahead_24H_RBFNN_Forecast.csv

BEGIN
    Validate required files:
        cleaned data exists
        planned outage workbook exists
        saved model, scaler, and metadata files exist for all plants

    Load cleaned data.
    Load planned outage table.
    Load saved RBFNN model bundle for each plant.

    Initialize empty 24-hour forecast table.

    FOR forecast hour h from 1 to 24 DO
        FOR each plant in cascade order DO
            Build feature row from the latest history.
            Apply the saved input scaler.
            Predict residual/delta generation using saved RBFNN.
            Inverse-transform predicted residual/delta.
            Add predicted residual/delta to current generation anchor.
            Apply saved shrinkage, bias, bin, hourly, profile, and ramp
            corrections.
            Read planned unit availability for hour h.
            Adjust forecast for available plant capacity and planned outages.
            Distribute plant total forecast to available units using learned
            unit weights and unit capacity limits.
            Save unit-level and plant-total forecast values.
            Append predicted plant total to recursive history so later forecast
            hours can use previous predicted values.
        END FOR

        Compute total cascade generation as the sum of plant totals.
    END FOR

    Validate forecast consistency:
        outage units must have zero generation
        unit values must not exceed unit capacities
        plant totals must equal unit sums
        cascade total must equal sum of plant totals

    Format forecast columns and hour labels.
    Save Excel and CSV forecast files.
END

7. BENCHMARK MODEL TRAINING AND FORECASTING
============================================================

ALGORITHM: Train and Forecast Random Forest and XGBoost Benchmarks

INPUT:
    Cleaned hourly dataset
    Planned outage template

OUTPUT:
    Saved benchmark model artifacts
    Benchmark validation/testing metrics
    Random Forest forecast workbook
    XGBoost forecast workbook

    Load cleaned data and planned outage input.
    Build the same general feature structure used for the forecasting task.

    FOR each plant DO
        Split records chronologically into training, validation, and testing.
        Select plant-specific feature columns.
        Run feature leakage audit.

        FOR each benchmark model in Random Forest and XGBoost DO
            Generate candidate hyperparameter configurations.

            FOR each candidate configuration DO
                Train the model on the training split only.
                Predict validation residual/delta generation.
                Convert residual/delta predictions to level forecasts.
                Tune validation-only calibration.
                Run rolling validation day-ahead scoring when required.
                Store score and candidate metadata.
            END FOR

            Select best candidate using validation-aware score.
            Evaluate selected benchmark on validation and testing sets.
            Save model payload:
                trained estimator
                feature list
                calibration data
            Save validation/testing metrics and prediction rows.
        END FOR
    END FOR

    Save benchmark fairness audit and model selection audit.
    Generate operational 24-hour Random Forest and XGBoost forecasts.
    Save forecast workbooks and CSV files.
    Run leakage-safe rolling day-ahead backtests for benchmarks.
    Save benchmark backtest predictions and metrics.
END

============================================================
9. LEAKAGE-SAFE ROLLING 24-HOUR DAY-AHEAD BACKTEST
============================================================

ALGORITHM: Rolling Day-Ahead Validation and Testing Backtest

INPUT:
    Cleaned hourly dataset
    Saved model artifacts
    Chronological split boundaries

OUTPUT:
    Day-ahead validation predictions and metrics
    Day-ahead testing predictions and metrics
    Backtest metadata

BEGIN
    Determine valid forecast days with complete 24-hour actual records.
    Assign days to validation and testing ranges based on chronological split.

    FOR each split in validation and testing DO
        Initialize empty prediction rows.

        FOR each forecast day in the split DO
            Create history using only rows before 00:00 of the forecast day.
            Reject the case if history includes any same-day forecast records.

            Build outage plan from last-known historical outage/status values.
            Do not use same-day actual unit outage/status values for the
            primary leakage-safe backtest.

            Generate recursive 24-hour forecast from saved model artifacts.

            Load actual generation for the same forecast day.
            FOR each plant and each forecast hour DO
                Save forecast date, hour, plant, actual generation, predicted
                generation, and model name.
            END FOR
        END FOR

        Compute split metrics by plant:
            operational MAPE
            MAE
            RMSE
            R2
            number of forecast days
            number of forecast hours
            MAPE inclusion and exclusion counts

        Save prediction workbook.
        Save metrics workbook.
    END FOR

    Save summary metadata:
        split strategy
        models included
        outage input rule
        same-day actual outage usage flag = false
        future data used flag = false
        testing used for training or tuning flag = false
END


============================================================
10. OPERATIONAL MAPE CALCULATION
============================================================

ALGORITHM: Compute Operational MAPE

INPUT:
    Actual generation values
    Predicted generation values
    Plant name

OUTPUT:
    Operational MAPE percentage

BEGIN
    Determine plant-specific operational threshold.

    FOR each actual and predicted pair DO
        IF actual generation is greater than or equal to the operational
        threshold THEN
            Include row in MAPE calculation.
        ELSE
            Exclude row from MAPE calculation because percentage error is not
            meaningful near zero generation.
        END IF
    END FOR

    IF no rows remain after filtering THEN
        Return missing or undefined MAPE.
    ELSE
        Compute absolute percentage error for included rows:
            abs(actual - predicted) / abs(actual) * 100
        Return the mean absolute percentage error.
    END IF
END


============================================================
11. PLANNED OUTAGE-AWARE UNIT ALLOCATION
============================================================

ALGORITHM: Allocate Plant Forecast to Available Units

INPUT:
    Plant-level generation forecast
    Planned unit status for the forecast hour
    Historical unit generation shares
    Unit capacity table

OUTPUT:
    Unit-level generation forecast values

BEGIN
    Identify available units where planned status = 1.
    Identify unavailable units where planned status = 0.

    FOR each unavailable unit DO
        Set unit generation forecast to 0.
    END FOR

    Compute available plant capacity as the sum of capacities for available
    units.

    Limit plant forecast so it does not exceed available plant capacity.

    Estimate unit allocation weights:
        Prefer learned historical unit shares for the plant and hour.
        Fall back to capacity-based shares when historical shares are not
        sufficient.

    FOR each available unit DO
        Assign generation = plant forecast * unit allocation weight.
        Clip assigned generation between 0 and the unit capacity.
    END FOR

    IF sum of assigned unit generation differs from plant forecast THEN
        Redistribute remaining generation across available units with unused
        capacity.
    END IF

    Set plant total equal to the final sum of unit forecasts.
END

13. STREAMLIT DASHBOARD CONTROL LOGIC
============================================================

ALGORITHM: Dashboard Operation

INPUT:
    User actions in Streamlit dashboard
    Existing project files

OUTPUT:
    Updated cleaned files, outage plan, forecasts, charts, downloads, and
    status displays

BEGIN
    Configure Streamlit page title and wide layout.
    Define project paths for data, outputs, models, metadata, and scripts.
    Define model configuration for RBFNN, Random Forest, and XGBoost.

    Render sidebar navigation:
        Dashboard Overview
        Data Management
        Planned Outage Planning
        Forecast
        System Information

    IF user opens Dashboard Overview THEN
        Load selected model forecast if available.
        Load cleaned data if available.
        Load outage plan if available.
        Display KPI cards, charts, file status, and testing CDF section.
    END IF

    IF user opens Data Management THEN
        Allow raw Excel upload.
        IF user clicks Refresh Data From Disk THEN
            Clear cached dashboard data.
        END IF
        IF user clicks Run Data Cleaning THEN
            Run scripts/cell1_clean_data.py as a subprocess.
            Show script output or error message.
            Reload cleaned data status.
        END IF
    END IF

    IF user opens Planned Outage Planning THEN
        Load Planned_Outages_Input.xlsx.
        Display editable outage/status table.
        IF user clicks Save Outage Plan THEN
            Save edited table to Excel.
        END IF
        IF user clicks Forecast Day-Ahead THEN
            Save edited outage table.
            Validate required forecast files and model artifacts.
            Run RBFNN forecast-only script.
            Run benchmark forecast-only script.
            Clear cached dashboard data.
            Display completion status.
        END IF
        IF user clicks Retrain RBFNN Model THEN
            Run scripts/cell2_rbfnn.py --train.
        END IF
        IF user clicks Retrain Benchmark Models THEN
            Run scripts/cell3_benchmark.py --train.
        END IF
    END IF

    IF user opens Forecast THEN
        Let user select model.
        IF user clicks Run selected model Forecast THEN
            Run the selected model's forecast-only script.
            Clear cached dashboard data after success.
        END IF
        IF user clicks Refresh Forecast Files THEN
            Clear cached dashboard data.
        END IF
        Load selected forecast workbook.
        Display KPIs, chart, forecast table, and Excel download button.
        Load all available model forecasts.
        Render total cascade model comparison chart and summary tables.
    END IF

    IF user opens System Information THEN
        Display workflow, file status, environment information, and system
        checks.
    END IF
END
